# FEAT0004 — Solver Algorithms — Chapters 1–3

## Goal

Implement actual solving capability for A=B Chapters 1–3 using the Solver Framework.

## Scope

Implement the solving algorithms required to automatically produce locally valid candidates for every project puzzle in Chapters 1–3.

Codex may freely determine the internal algorithmic design.

The implementation may use:

* shared algorithms across chapters;
* different algorithms per chapter;
* multiple cooperating strategies;
* heuristics;
* search;
* program synthesis;
* constraint solving;
* puzzle-specific methods;
* other suitable approaches.

No requirement exists that an algorithm generalize beyond the puzzles for which it is useful.

Implementation work such as adding heuristics, changing search strategies, introducing puzzle-specific handling, or restructuring algorithms remains internal to this feature rather than requiring separate features.

Any new third-party dependency requires owner approval before introduction.

## Constraints

Directly copying external solutions is prohibited.

Candidates must comply with the accepted Rules.

Search heuristics must not be incorrectly treated as A=B semantic restrictions.

A final candidate for a puzzle must satisfy the local-validity requirements defined in `REQUIREMENTS.md`.

## Verification

The primary verification evidence is domain-level solving capability rather than an arbitrary conventional unit-test target.

For every project puzzle in Chapters 1–3, Solver must automatically produce a final serialized candidate that:

* satisfies `min_lines`;
* passes the complete exported input/output dataset through the project execution system.

Applicable low-cost unit or regression tests should still be used for algorithm-supporting components where they provide meaningful value.

Codex must self-review the implementation and solving results before owner review.

## Acceptance

FEAT0004 is ready for owner review when all project puzzles in Chapters 1–3 have locally valid automatically produced candidates.

Final feature acceptance belongs to the owner. Real-game validation governs final puzzle acceptance and project completion separately under `REQUIREMENTS.md`.

Acceptance of FEAT0004 does not constitute final project completion.
