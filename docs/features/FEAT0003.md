# FEAT0003 — Implement Solver Framework

## Goal

Implement the common high-level execution framework used by concrete A=B solving algorithms without defining a universal solving algorithm.

## Scope

The Solver Framework must provide the common lifecycle required to:

1. receive a puzzle identifier;
2. resolve the corresponding puzzle data;
3. obtain the applicable Rules;
4. create or invoke an appropriate solving algorithm;
5. receive tentative candidates from that algorithm;
6. invoke Executor for search-time trial execution;
7. collect Executor feedback;
8. return relevant feedback to the solving algorithm;
9. allow the algorithm to adjust and continue;
10. repeat until the Solver decides to submit a candidate or terminates abnormally.

The framework must define a common Solver-level API between itself and concrete solving algorithms.

Concrete algorithms may differ completely in their internal implementation.

The common API must be sufficient for the framework to invoke an algorithm and exchange the candidate/feedback information required by the Solver lifecycle.

Exact API classes, message structures, and algorithm internals are implementation decisions.

## Out of Scope

* a universal solving algorithm;
* solving any particular real puzzle;
* chapter-specific solving capability;
* requiring one algorithmic approach across chapters;
* Manager-level orchestration;
* project-wide full validation.

## Verification

Testing should use a minimal dummy/mock solving algorithm.

The test algorithm exists only to exercise the Solver Framework and is not expected to solve a real A=B puzzle.

Verification must demonstrate at least:

* correct puzzle/Rules resolution;
* correct algorithm invocation;
* tentative-candidate exchange;
* Executor invocation;
* feedback return to the algorithm;
* repeated Solver loop operation;
* final candidate submission behavior;
* appropriate abnormal-error propagation.

Debug behavior should allow useful observation of the Solver lifecycle without intentionally altering its logic.

A real chapter Solver is not required for FEAT0003 verification.

Codex must run applicable tests and perform self-review before owner review.

## Acceptance

FEAT0003 is accepted based on correctness of the common Solver execution framework.

Solving a real project puzzle is not an acceptance condition for this feature.

Final feature acceptance belongs to the owner.
