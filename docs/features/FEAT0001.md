# FEAT0001 — Formalize A=B Rules

## Goal

Convert the official natural-language rules for all six A=B chapters into the single machine-readable Rules definition required by the project.

## Scope

Codex must:

* read and understand the official chapter rule documentation;
* design an appropriate structured Rules representation;
* produce one YAML Rules file covering all six chapters;
* represent instruction availability by chapter;
* represent the instruction information required by later Executor and Solver implementation;
* define appropriate machine identifiers, operation names, parameter names, and related structural conventions.

Codex may independently design the Rules schema and implementation-oriented naming.

Rules must represent A=B semantics rather than Solver-specific search knowledge.

## Out of Scope

* Executor implementation;
* Solver implementation;
* automatic natural-language parsing;
* a generic DSL for hypothetical future rule systems;
* unit tests for runtime instruction behavior.

## Verification

No unit-test suite is required for this feature.

Before review, Codex must self-review the generated Rules and verify at least:

* valid YAML syntax;
* internally coherent structure;
* coverage of all six chapters;
* coverage of the documented instructions and chapter availability;
* no obvious discrepancy with the official natural-language rules;
* no Solver-specific heuristics incorrectly encoded as authoritative Rules.

## Acceptance

The feature is ready for owner review after Codex verification succeeds.

The owner reviews the Rules against the official documentation.

FEAT0001 is `ACCEPTED` only after owner approval.

Later implementation based on the authoritative Rules should not proceed until this feature is accepted.
